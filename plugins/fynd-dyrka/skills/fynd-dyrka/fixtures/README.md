# Фикстуры — регрессия для промптов фан-аута

Подопытные репозитории с известным ответом. Нужны, чтобы правка шаблона промпта
проверялась замером, а не ощущением. Каждая фикстура отвечает на один вопрос.

Прогон: скопируй шаблон промпта из `references/fanout.md`, подставь путь к
фикстуре, запусти **две реплики** (одна врёт про воспроизводимость), сравни с
таблицей ниже. Реплики гоняй на рабочей модели — на других цифры будут другими.

## `slice-not-fence/` — уходит ли агент за границу выданного среза

Срез агенту: `app/api/routes.py`. Эндпоинты корректно вызывают проверки, обе
дырки — в `app/lib/urlcheck.py`, вне среза.

| Что должен найти | Где |
|---|---|
| `host.endswith(allowed)` пропускает `evilexample.com` | `app/lib/urlcheck.py` |
| список строковых префиксов не ловит `localhost`, `::1`, `172.16/12`, decimal IP | `app/lib/urlcheck.py` |
| `requests.get` без `allow_redirects=False` | `app/api/routes.py` |

**Провал:** агент остаётся в выданном файле, пишет «вне разрешённой зоны» и
возвращает шаблонные гипотезы (DNS rebinding, `::ffff:`) без строки кода.

Замер 16.08.2026: старый шаблон 0/2 реплик, новый 2/2.

## `swarm-territory/` — покрывает ли инвентарь не-HTTP входы

Территория целиком. Одна дырка в HTTP-поверхности, четыре — вне её.

| Что должен найти | Где |
|---|---|
| IDOR: `get_report` не фильтрует по `owner_id` | `db/queries.py` |
| командная инъекция, `shell=True` + `%` | `ops/cleanup.py` (два места) |
| SQL-инъекция в `DELETE` через `%` | `ops/cleanup.py` |
| `pickle.loads` из файла состояния | `ops/rotate.py` |
| SQL-инъекция через `.format(**params)` + `executescript` | `db/migrate.py` |
| цепочка: `restore_archive` распаковывает в каталог, откуда `load_state` читает pickle → RCE | `ops/` |

**Ловушка на ложное срабатывание:** `list_reports` собирает `LIMIT %d`
форматированием, но `int(limit)` в роуте кастует раньше — инъекции нет. Агент,
заявивший её находкой, не проверил путь до конца.

Замер 16.08.2026: инвентарь по HTTP-точкам входа 1/5, открытая территория 5/5.

## `toctou-and-fp/` — ловит ли агент check-vs-use и убивает ли свою гипотезу

Писалась как заведомо чистая: точное сравнение хоста с обязательной точкой,
классификация адресов через `ipaddress.is_global`, `ipv4_mapped`,
`allow_redirects=False`. Восемь ассертов на классификацию проходят.

Чистой она не оказалась — и в этом её ценность.

| Что должен найти | Почему ассерты его не поймали |
|---|---|
| TOCTOU: `is_internal_host` резолвит хост, `requests.get` резолвит заново, IP не пиннится → DNS rebinding | ассерты проверяли классификацию адресов, а не связку проверка-использование |

**Ловушка на ложное срабатывание:** backslash-дифференциал
(`http://evil.com\@example.com/` — Python `urlparse` видит `example.com`,
браузер по WHATWG обрывает на `\`). По коду и по тексту спецификации выглядит
живым, но Werkzeug экранирует `\` в `%5C`, и дифференциал умирает. Снимается
**только прогоном** — через `Flask.test_client()` и реальный браузер.

Замер 17.08.2026: реплика, сверявшаяся со спецификацией, заявила байпас
кандидатом; реплика, поднявшая venv и прогнавшая запрос, сняла гипотезу.
Разница не в модели и не в промпте, а в 18 обращениях к инструментам против 8.

Цена правила «дойди до реализации проверки»: 91-100k токенов и 6-9 минут против
62k и 50 секунд у агента, читающего только срез.

## Чего фикстуры не проверяют

Все три — синтетика на 5-9 файлах, и территория в них исчерпывается за два
раунда. Поведение роя на настоящем репо (тысячи файлов, `MAP` не строится,
критерий остановки не срабатывает) **не проверено ничем**. Первый же реальный
аудит стоит прогнать как замер и дописать сюда.
